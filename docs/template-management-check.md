# 템플릿 관리 점검 (2026-10-08)

목록·생성·복제·활성화·사이트 담기·썸네일·프리뷰·정보 수정·가져오기/내보내기·삭제·적용 기록의 UI와 API를 검토했다.

## 수정

- GitHub Pages 썸네일: templates/*/thumbs의 실제 JPG와 촬영 정보를 Vite 자산으로 포함한다. Basic·인테리어·치과의 메인/서브 모두 포함하며 배포 하위 경로와 캐시용 파일 해시가 적용된다.
- Basic 복사본 프리뷰: 기본 제공 여부 대신 디자인 구성으로 보관된 페이지 소스를 찾는다.
- 데모 정보 보기/수정: 기본 정보를 표시하고 라이선스·요구 버전·요구 기능·변경 이력을 브라우저 저장소에 유지한다. 파일 분석은 로컬에서 제공한다.
- 데모 내보내기: 서버 없는 /api 주소 요청 대신 구성 JSON을 다운로드한다. ZIP 설치 시 로컬 이용 안내를 표시한다.
- 로컬 복제: 라이선스·요구 버전·요구 기능·변경 이력을 함께 복제한다.
- ZIP 가져오기: 설치된 폴더 이름으로 매니페스트를 갱신한다. 폴더 이동 후 실패해도 이동된 임시 템플릿을 정리한다.
- 파일 없는 템플릿 내보내기: 다른 디자인의 현재 사이트를 자동으로 담지 않고 명확한 오류를 반환한다.

## 검증

- 웹/API TypeScript 검사 통과.
- GitHub Pages와 같은 VITE_DEMO=true, BASE_PATH=/wnc_home_01/ 빌드 통과.
- 별도 Playwright 브라우저에서 데모 API를 실행해 3개 템플릿의 6개 이미지 HTTP 응답, Basic 복사본 프리뷰 경로, 정보 수정·조회·내보내기, 활성 템플릿 1개 유지, 사용 중 삭제 차단, 사이트 담기, 비활성 복사본 삭제를 확인했다.
- git diff --check 통과.

## 범위와 제한

GitHub Pages 변경 사항은 브라우저 localStorage에 저장되며 로컬 DB와 동기화되지 않는다. 새 촬영·ZIP 설치·소스 편집·파일 백업 복원은 로컬 서버 기능이다. 로컬의 활성화와 파일 복원은 실제 사이트 파일/DB를 변경하므로 이번 점검에서는 실행하지 않고 코드와 타입을 검토했다. 임의의 신규 디자인을 Pages에 추가할 때는 데모 디자인 등록과 함께 배포해야 한다.

기존 빌드 경고(큰 JS 청크, Bitcoa 폰트 경로)는 이번 템플릿 관리 수정과 별개로 남아 있다.
